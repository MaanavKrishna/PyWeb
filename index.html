Plain variables are reactive

No Signal(0), no hooks. The compiler sees count read by markup and mutated by an event, lowers it to a signal, and patches only the affected text node — no virtual DOM. Everything below is the actual compiler output for this source, generated when this site was built:

from pyweb import App


app = App()


@app.page("/")
def Home():
    count = 0


    def increment():
        count += 1


    <main>
        <h1>Counter</h1>


        <button onclick={increment}>
            Count: {count}
        </button>
    </main>

import { sig, computed, bind_text, bind_input, on, rpc, mutate, liveList, liveIf, takeover, dynText } from './runtime.js';

export const count = sig(0); // pyweb:count
export function increment(e) { count(count() + 1) } // pyweb-line:12
window.__pyweb_scope = { count, increment };
export function mount(root=document) {
  // static — no bindings
  on(root, 'click', increment, 'pw00001'); // line 20
  bind_text(root, "count", () => (count())); // line 21
}
if (typeof document !== 'undefined') {
  if (document.readyState === 'loading') {
    document.addEventListener('DOMContentLoaded', () => mount(document));
  } else { mount(document); }
}

Everything a production app needs

🔒 Secure by default

Parameterized SQL only, escaped templates, signed sessions, secret-leak compile errors, upload validation. pyweb check gates CI.

🔍 Every magic is inspectable

pyweb inspect prints placement decisions and reasons per symbol — browser vs server, and why.

🔄 Realtime + offline

Live queries push minimal patches over SSE/WebSocket; offline queue replays with LWW conflicts and optimistic UI.

🗄 Real databases

Postgres/MySQL/SQLite, pooling, prepared statements, streaming, retries, versioned migrations with journal and rollback.

🧪 Tests without a browser

Virtual-browser client for full-stack tests; real-browser hooks when you need them.

📦 Deploy anywhere

pyweb build --production emits hashed assets + manifest; pyweb serve runs threaded with /healthz. No lock-in.

Honest scope (v1.0): streaming SSR, the WASM browser target, and native mobile renderers are roadmap — see the roadmap page for what is real, preview, and future. No vaporware.
