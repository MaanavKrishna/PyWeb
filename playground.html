Compiler playground

A guided tour of the six compiler stages, using the real artifacts produced for the counter app when this page was built. Nothing here is a mockup.

Stage 1 · Parse

Markup inside Python becomes UI nodes in a unified AST alongside normal statements. The counter yields one page, one handler, one binding.

Stage 2 · Reactivity

compute_reactive finds count read by markup and mutated by increment → signals: count.

Stage 3 · Placement

Effect + security graphs assign every symbol. increment is browser-safe; __page__ is browser+server (SSR + activation).

Stage 4 · RPC

@server functions become endpoint + typed stub + validation + auth + CSRF + retries. This app has none — so zero RPC bytes ship.

Stage 5 · SSR

Initial HTML renders on the server with binding anchors (data-pw-id), so first paint needs no JS.

Stage 6 · Browser codegen

Fine-grained JS: one signal, one text binding, one event listener. 649 bytes of page JS plus the shared runtime.

import { sig, computed, bind_text, bind_input, on, rpc, mutate, liveList, liveIf, takeover, dynText } from './runtime.js';

export const count = sig(0); // pyweb:count
export function increment(e) { count(count() + 1) } // pyweb-line:12
window.__pyweb_scope = { count, increment };
export function mount(root=document) {
  // static — no bindings
  on(root, 'click', increment, 'pw00001'); // line 20
  bind_text(root, "count", () => (count())); // line 21
}
if (typeof document !== 'undefined') {
  if (document.readyState === 'loading') {
    document.addEventListener('DOMContentLoaded', () => mount(document));
  } else { mount(document); }
}
